=========================================================
  РУКОВОДСТВО ПО custom_params (config.json)
=========================================================

custom_params — это список параметров, которые нейронка обязана (или может)
вернуть в поле "custom_fields" JSON-ответа. Движок автоматически читает
значения и применяет их к переменным персонажа.

---------------------------------------------------------
 ЗАЧЕМ
---------------------------------------------------------
Позволяет промтеру добавлять произвольные управляемые переменные персонажа
без написания постскрипт-правил для типовых случаев:
  - накопительные показатели (Love, Fear, Trust...)
  - флаги состояния (secret_trial, quest_active...)
  - числовые модификаторы (tension_level, mood_score...)


=========================================================
 ПОЛЯ ПАРАМЕТРА
=========================================================

ОБЯЗАТЕЛЬНЫЕ
─────────────
  "name"          Имя переменной персонажа (Python-идентификатор).
                  Это то, что хранится в character.variables и видно в отладке.
                  Пример: "Love", "Fear", "TrustLevel"

  "type"          Тип значения, которое пишет нейронка:
                    "float"   — дробное число (default)
                    "int"     — целое число
                    "bool"    — true/false
                    "str"     — строка


ИДЕНТИФИКАЦИЯ ПОЛЯ В JSON-ОТВЕТЕ
─────────────────────────────────
  "change_command"  Имя поля, которое нейронка пишет в custom_fields.
                    Если не указано — совпадает с "name".

                    Пример: name="Love", change_command="love_change"
                    → нейронка пишет: "custom_fields": { "love_change": 2 }
                    → переменная Love обновляется

                    Используй change_command чтобы имя поля в промте
                    было понятно нейронке ("love_change" говорит само за себя),
                    а имя переменной оставалось читаемым ("Love").


ПОДСКАЗКИ ДЛЯ НЕЙРОНКИ
───────────────────────
  "description"   Описание поля — вставляется в схему, которую видит нейронка.
                  Объясни когда и как использовать параметр.
                  Пример: "Change in Love level. +1..+5 for warm moments,
                           -1..-5 for cold/hostile ones."

  "required"      true  — нейронка обязана вернуть поле каждый раз (default)
                  false — поле необязательное

  "nullable"      true  — разрешено вернуть null (только для required=false)


ОГРАНИЧЕНИЯ НА ВВОД (что пишет нейронка)
─────────────────────────────────────────
  "change_min" / "change_max"
                  Допустимый диапазон изменения, присылаемого нейронкой.
                  Движок клампит входное значение в этот диапазон ПЕРЕД
                  любыми вычислениями.
                  Также передаётся нейронке как подсказка в схеме JSON.
                  Пример: change_min=-10, change_max=10 → нейронка не может
                           прислать 50

  "max_change"    Максимальное абсолютное изменение за один ответ.
                  Работает только с op="add". Клампит после change_min/change_max.
                  Пример: max_change=5 → за один ход Love изменится не более
                           чем на 5, даже если нейронка прислала -10


ИНИЦИАЛИЗАЦИЯ ПЕРЕМЕННОЙ
─────────────────────────
  "initial"       Начальное значение переменной "name" при первом запуске
                  (когда в истории её ещё нет).
                  При перезапуске значение берётся из истории — не сбрасывается.
                  Пример: "initial": 1   → Love = 1 при чистом старте


ПРИМЕНЕНИЕ ЗНАЧЕНИЯ К ПЕРЕМЕННОЙ
────────────────────────────────────────────────────────
Есть два взаимоисключающих подхода: формула ИЛИ op.

  [Вариант A] Формула (гибко)
  ────────────────────────────
  "formula"       Python-выражение, результат которого записывается в переменную.
                  Вычисляется ПОСЛЕ клампа входного значения (change_min/change_max, max_change).

                  Доступные имена в формуле:
                    <name>          — текущее значение переменной
                    <change_command> — (уже зажатое) значение от нейронки
                    current         — то же, что <name>
                    value           — то же, что <change_command>

                  Доступные функции: max, min, abs, int, float, round

                  Примеры:
                    "max(1, min(Love + love_change, 300))"
                    "max(0, min(current + value * 2, 100))"
                    "round(Love + love_change, 1)"

  [Вариант B] Op + bounds (просто)
  ──────────────────────────────────
  "op"            Операция над переменной:
                    "add"  — переменная += входное значение
                    "set"  — переменная  = входное значение

  "min" / "max"   Диапазон допустимых значений переменной ПОСЛЕ операции.
                  Работает и с op, и с formula (как страховка после формулы).
                  Пример: min=0, max=300


ПОРЯДОК ПРИМЕНЕНИЯ (для справки)
─────────────────────────────────
  1. Нейронка пишет love_change = X
  2. X зажимается в [change_min, change_max]
  3. X зажимается в [-max_change, +max_change]  (если op=add)
  4a. Если задана formula → вычисляется new_val = formula(Love, X)
  4b. Иначе: op=add → new_val = Love + X; op=set → new_val = X
  5. new_val зажимается в [min, max]  (если заданы)
  6. Love = new_val


=========================================================
 ПРИМЕРЫ
=========================================================

── Пример 1: Накопительный Love (формула) ──────────────
{
    "name": "Love",
    "change_command": "love_change",
    "type": "float",
    "description": "Изменение уровня привязанности. +1..+5 за тёплые моменты, -1..-5 за холодные.",
    "required": true,
    "change_min": -10,
    "change_max": 10,
    "initial": 1,
    "formula": "max(1, min(Love + love_change, 300))"
}

── Пример 2: Тот же Love через op (без формулы) ─────────
{
    "name": "Love",
    "change_command": "love_change",
    "type": "float",
    "description": "Изменение уровня привязанности.",
    "required": true,
    "change_min": -10,
    "change_max": 10,
    "initial": 1,
    "op": "add",
    "min": 1,
    "max": 300
}

── Пример 3: Уровень страха с ограничением скачка ───────
{
    "name": "Fear",
    "change_command": "fear_change",
    "type": "float",
    "description": "Изменение уровня страха персонажа. +1..+3 при угрозах, -1..-2 при успокоении.",
    "required": true,
    "change_min": -5,
    "change_max": 5,
    "max_change": 3,
    "initial": 0,
    "op": "add",
    "min": 0,
    "max": 100
}

── Пример 4: Булевый флаг (необязательный) ──────────────
{
    "name": "secretTrial",
    "change_command": "secret_trial",
    "type": "bool",
    "description": "Активировать режим испытания. Вернуть true только если игрок прошёл проверку.",
    "required": false,
    "nullable": true,
    "op": "set"
}


=========================================================
 ПОСТСКРИПТЫ И custom_params: ЧТО ВЫБРАТЬ
=========================================================

Используй custom_params (config.json) когда:
  ✓ Простая математика: прибавить, установить, зажать
  ✓ Хочешь чтобы всё было в одном месте
  ✓ Нет условной логики

Используй постскрипт (PostScripts/main_rules.postscript) когда:
  ✓ Условная логика: IF attitude < 30 THEN ...
  ✓ Нужно менять несколько переменных одним полем
  ✓ Сложные выражения со встроенными переменными персонажа

Можно использовать оба: custom_params обрабатывается ПЕРВЫМ,
затем постскрипт. Для одного поля лучше выбрать что-то одно,
иначе переменная обновится дважды.


=========================================================
 ПЕРЕМЕННЫЕ ДОСТУПНЫЕ В ФОРМУЛАХ И ПОСТСКРИПТАХ
=========================================================

Стандартные (всегда есть):
  attitude, boredom, stress   — основные показатели
  secretExposed               — раскрыт ли секрет
  current_fsm_state           — текущее состояние FSM
  player_name, player_name_known

Кастомные (из этого же конфига):
  Любая переменная из "name" доступна по своему имени.
  Пример: если задан {"name": "Love", ...}, то в формулах и
  постскриптах используй просто Love.
