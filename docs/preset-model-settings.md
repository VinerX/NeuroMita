# Настройки модели у API-пресета

Параметры генерации принадлежат API-пресету. В разделе «Модели» остаются поведение запросов, попытки и задержки, ожидание, включение стриминга, схема ответа приложения, выбор инструментов и реакции. Эти настройки не определяют имена параметров API.

Описание параметров — версионированный JSON. Оно содержит типы, значения по умолчанию, ограничения, пояснения и точные пути полей в HTTP JSON. Готовый шаблон автоматически задаёт описание. Пользователь меняет значения и включает нужные поля; выбирать разновидность thinking или формат параметров в готовом шаблоне не требуется. Сопоставления названий моделей для новых настроек нет.

У пресета без шаблона формат определяется существующей настройкой «Формат запроса» в расширенных настройках подключения. Google использует `generationConfig`, OpenAI Compatible — поля объекта запроса. Параметр `settings_schema_id` в определении протокола задаёт стартовый набор; шаблон может уточнить его для конкретного провайдера. Это связь с форматом API, а не классификация моделей.

## Роли модулей

- `src/model_settings/schema.py`: контракт данных, проверка определений и значений, компиляция точных JSON-путей. Не импортирует Qt, HTTP-клиенты или настройки GUI.
- `src/model_settings/repository.py`: каталог JSON, ресурсы внутри `.pyz`, атомарная установка обновлений. Изменения внешних файлов обнаруживаются без перезапуска; неизменённые определения кэшируются.
- `src/model_settings/service.py`: выбор определения, состояние пресета, импорт/экспорт и ограничения возможностей модели.
- `src/model_settings/migration.py`: однократный перенос прежних общих параметров и оверрайдов. Старые model profiles используются только для переноса старого контракта.
- `PresetModelSettingsController`: связывает приложение с формой и диалогами.
- `ModelSettingsForm`: отображает поля из определения, собирает ввод и показывает результат доменной проверки.
- `ModelParametersDialog`: визуальное добавление, изменение и удаление деклараций параметров; отдельная вкладка JSON для расширенного редактирования. Проверку полного определения выполняет сервис через GUI-контроллер.
- `ApiPresetResolver`: получает готовые параметры и возможности выбранного пресета, включая резервные пресеты.
- Провайдеры получают `LLMRequest.native_parameters`. Google берёт `generationConfig`, HTTP OpenAI Compatible использует готовые поля, OpenAI SDK передаёт их через `extra_body`. Старые преобразования не вызываются для нового контракта.

## JSON и обновления

При первом обращении встроенные определения записываются в `Settings/APIModelSchemas`. Стартовые наборы включают Google Gemini, OpenAI Compatible, Mistral, OpenRouter, Groq, Together и локальный OpenAI Compatible. Остальные OpenAI-совместимые шаблоны используют общий контракт. Старые бюджетные определения Google сохраняются для точного однократного переноса прежних настроек; списка выбора этих вариантов в форме нет.

Чтобы обновить определение, измените JSON, увеличьте `revision` и импортируйте файл либо замените файл в каталоге. `id` должен остаться прежним. Существующие значения пресетов сохраняются. Новые поля получают значение по умолчанию и остаются выключенными у существующих пресетов. У новых пресетов применяется `enabled_by_default`.

Изменение ограничений может сделать прежнее значение недопустимым: поле подсвечивается, сохранение и отправка запроса блокируются. Если включённое поле удалено из JSON, его нужно явно выключить в форме; оно не отправляется молча по старому пути.

Пример нового параметра в существующем OpenAI-совместимом протоколе:

```json
{
  "schema_version": 1,
  "id": "my-provider",
  "revision": 1,
  "title": {"ru": "Мой провайдер", "en": "My provider"},
  "dialect": "openai_chat_completions",
  "fields": [
    {
      "id": "seed",
      "title": {"ru": "Случайное зерно", "en": "Random seed"},
      "description": {"ru": "Фиксированное зерно генерации.", "en": "Fixed generation seed."},
      "type": "integer",
      "default": 42,
      "minimum": 0,
      "enabled_by_default": false,
      "path": ["vendor_settings", "seed"]
    }
  ]
}
```

Включённое поле с `value = 123` создаёт `{"vendor_settings": {"seed": 123}}` без нового Python-маппинга. Поддерживаются `number`, `integer`, `boolean`, `string`, `array`, `object`; списки `enum`, числовые границы, ограничения длины, специальные числовые значения и группы взаимоисключающих параметров. `0` и `false` сохраняют своё значение.

Пресет хранит состояние отдельно:

```json
{
  "version": 1,
  "schema_id": "my-provider",
  "values": {"seed": 123},
  "enabled": ["seed"]
}
```

Кнопка «Настроить параметры» открывает редактор полей. Можно добавить параметр, указать название, ключ, тип, дефолт, числовые ограничения, допустимые значения и пояснение. Вложенные ключи записываются через точку; для Google префикс `generationConfig` добавляется автоматически. Отдельная вкладка JSON позволяет менять все декларативные свойства, включая специальные значения и группы взаимоисключения. Протокол подключения в этом редакторе не меняется.

Сохранение редактора создаёт полное `schema_override` только у этого пресета. Такой пресет использует своё описание вместо общего каталога. Удалённые вручную поля выключаются; новые поля получают дефолт и остаются выключенными до явного включения. Импорт определения повторно подключает пресет к каталогу. Экспорт полного API-пресета включает описание, поэтому его можно импортировать на другом компьютере без установки отдельного файла определения.

`supports` в определении и `support_overrides` у пресета описывают поддержку `structured_output`, `tools_native`, `streaming`. Поддержка нативной схемы управляет только её передачей провайдеру: JSON-контракт приложения сохраняется. Возможности пресета не включают инструменты или стриминг вопреки общим настройкам и не расширяют возможности протокола.

Поля модели не могут переписать сообщения, модель, авторизацию, инструменты, стриминг, маршрутизацию и схему ответа. Это отдельные роли в сборке запроса. Новый формат API с другой структурой сообщений или ответов требует транспортного адаптера; JSON обновляет параметры существующих протоколов.

## Google и совместимые API

Готовый набор Google содержит обычные поля `thinkingLevel` и `thinkingBudget`. Исходно отправляется `thinkingLevel: low`, бюджет выключен; эти поля нельзя включить одновременно. Низкий уровень не называется отключением мышления: Gemini 3 не поддерживает полное thinking-off. Неподходящие уровни можно исключить из `enum` своего определения. Старое внутреннее имя набора `google-level` используется как идентификатор файла и не показывается как режим пользователю.

Для `thinkingBudget`: `0` — отключение при поддержке модели, `-1` — динамический бюджет. Ограничения зависят от сервера и модели. Миграционные определения сохраняют прежние ограничения 2.5 Pro и Flash-Lite: Pro не принимает отключение через `0`; Flash-Lite допускает специальные значения `0`, `-1` и положительные бюджеты от 512. Для нового кастомного определения ограничения задаются в JSON, без Python-маппинга названия модели. У Google лимит выходных токенов включает токены размышлений.

OpenAI-совместимость не гарантирует поддержку каждого параметра каждым сервером или моделью. Например, Groq ограничивает некоторые поля OpenAI, а OpenRouter имеет вложенный объект `reasoning`. Определение описывает конкретную структуру и ограничения; отсутствие галочки означает отсутствие параметра в запросе. Серверные ограничения, которых нет в JSON, по-прежнему могут привести к ответу 400 — локальная проверка не имитирует неизвестный контракт сервера.
