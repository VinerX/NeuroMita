# External TTS для NeuroMita

## Цель

Добавить экспериментальный третий вариант озвучки `External`, который отправляет подготовленный текст на пользовательский HTTP-сервис, получает локальный WAV и использует существующее воспроизведение NeuroMita. F5-TTS, RVC, Docker и модели остаются на стороне пользователя. Реализация рассчитана на отдельную тестовую ветку и должна оставить TG и Local рабочими без изменений поведения.

## Пользовательский сценарий

Пользователь выбирает `External`, указывает базовый URL API и, если сервер защищён, API-ключ. Необязательный идентификатор профиля выбирает серверную конфигурацию голоса/цепочки движков. Кнопка проверки подключения выполняет только health-запрос. Во время обычного запроса клиент отправляет текст и данные персонажа, скачивает WAV во временный локальный файл, проверяет его и передаёт путь существующему игровому или desktop playback пути.

## Протокол NeuroMita External TTS API v1

- `GET /v1/health`: `200` JSON с `{"status":"ok","api_version":1}`. Проверка не синтезирует тестовую фразу.
- `POST /v1/synthesize`: JSON `{ "request_id": "...", "text": "...", "character_id": "...", "voice_id": "..." }`; отсутствующие необязательные поля передаются как `null`.
- Успех: `200`, `Content-Type: audio/wav` (допускается `audio/x-wav`), тело — PCM WAV, 1–2 канала, 16-bit предпочтительно, sample rate 16–48 kHz.
- Ошибка HTTP не должна сохраняться как аудио. Для авторизации используется `Authorization: Bearer <api_key>`.
- Сервер сопоставляет `voice_id` с собственной конфигурацией; клиент не передаёт имена контейнеров, пути к моделям или внутренние адреса сервисов.

## Архитектура

### Конфигурация и клиент

Создать `src/services/external_tts_service.py` с неизменяемым `ExternalTTSConfig` и `ExternalTTSClient`. Настройки запроса копируются в конфигурацию один раз на запрос. `aiohttp` уже является зависимостью проекта. Клиент выполняет URL/тайм-аут валидацию, health-check и синтез; использует короткий connect timeout и конечный общий timeout; не повторяет синтез автоматически.

URL допускает только HTTP/HTTPS, без userinfo, query или fragment и с корректным портом. TLS-проверка не отключается. Ограниченный по размеру WAV загружается порциями в уникальный `.part` файл в каталоге аудио приложения. Стандартный модуль `wave` проверяет заголовок, параметры PCM, число каналов, частоту и наличие кадров. После успешной проверки временный файл атомарно переименовывается; ошибка и отмена удаляют незавершённый файл. Логи не содержат API-ключ или полный текст.

### Сервисный lifecycle

Добавить контракт `ExternalVoiceService` (health и synthesize с текстом, character_id и voice_id) в `src/services/contracts.py`. Зарегистрировать его реализацию через optional feature manager в `MainController`, включаемый при `USE_VOICEOVER` и `VOICEOVER_METHOD == External`. Самостоятельного тяжёлого runtime или модели у клиента нет.

### Аудиопоток

В `AudioController._on_voiceover_requested()` добавить External routing. External и Local передают полученный путь одному post-processing пути, чтобы сохранить `tts.ready`, task status, доставку Unity только при `task_uid` и активном game link, локальное воспроизведение/громкость, UI-статусы, флаг ожидания и performance trace. Метод External не должен передавать Unity сетевой URL.

### Настройки UI

В настройках озвучки добавить External в существующий список методов и отдельную секцию External: базовый URL, API-ключ (замаскированный ввод), voice ID, тайм-аут и кнопку проверки соединения. Поля отображаются только для External; Local/TG секции сохраняют прежнюю видимость. Обработчик проверки использует тот же сервис и показывает понятный результат без генерации звука. Значения хранятся в существующем settings registry.

### Диагностика

Использовать performance spans/marks проекта для времени ожидания внешнего API и получения WAV. Ошибки различают недоступность/тайм-аут, отказ авторизации, HTTP-ошибку, неверный WAV и превышение лимита ответа. Не логировать секреты.

## Ограничения первой версии

- Не устанавливать и не управлять Docker, F5-TTS, RVC или GPU.
- Не поддерживать специфичные API конкретных TTS-серверов и streaming/WebSocket.
- Не выполнять локальную перекодировку; сервер обязан возвращать поддерживаемый PCM WAV.
- Не делать автоматический retry синтеза и автоматический fallback на Local.
- HTTP допустим для явно настроенной локальной сети/VPN; для публичной сети пользователь настраивает HTTPS.

## Критерии готовности

- Выбор External не запускает Local TTS и корректно активирует External service.
- Health-check проверяет соединение без синтеза.
- Синтез отправляет ожидаемый контракт, валидирует ограниченный WAV и выдаёт локальный абсолютный путь.
- Ошибочные ответы, отмена и некорректные WAV не оставляют частичный файл и не помечаются успешной озвучкой.
- Путь проходит прежнюю развилку передачи в Unity либо проигрывания в desktop чате; TG и Local остаются доступны.
- Настройки и ошибки External доступны пользователю, секреты не попадают в логи.
