# 02. Качество и структура промптов персонажей

## Проблема

Объём и качество main-промптов различаются на **два порядка**, а крупные —
переросли в псевдокод, который LLM не исполняет.

Оценка объёма main-промптов (токены, грубо):
- Cappie ~33k, Kind ~20k, ShortHair ~10k, Mila ~10k, Ghost ~8k
- Crazy Default ~0.5k (+2k структуры), Creepy ~0.6k, Sleepy ~0.6k

Конкретика:
- **Cappie/Kind — «псевдокод-модули»**: сотни строк вида
  `IF Intent = "performed affection" THEN Activate; MaxLines = 3; ToneShift = [...]`.
  Модель не исполняет это как код — работает как размытый стилистический шум,
  съедающий контекст и внимание.
- У Cappie одна «IntimacySystem» — ~15 модулей с перекрёстными триггерами и
  счётчиками состояний, которых нет (`FinalTouchSceneCount ≥ 2`, «5 distinct
  SubtleTouchResponse across separate scenes» — никто их не считает).
- **`Kind/Default/Main/main.txt`: модуль «Internal Processing & Response
  Synthesis» вставлен дважды дословно** (~строки 21–83 и 106–167) → ~2k токенов
  в мусор. Там же: битые фразы, дублированный блок сна, legacy-механики
  (`*RP actions*`, `commands: ["walkto, PositionMita 1 Hall"]` со старым синтаксисом).
- **`Kind/Default/Structural/VariablesEffects.txt`: секция Attitude Tiers
  продублирована дважды** (см. также 05).
- Обратная крайность — Creepy/Sleepy: по два абзаца, без глубины, событий,
  вариативности.

## Предложения

- [ ] **P1.** Единый «скелет персонажа» с бюджетом ~2–3k токенов:
      identity + канон-биография (3–5 абзацев) + отношение к другим Митам +
      речевой стиль (5–8 правил + 5–10 коротких реплик-эталонов) +
      поведенческие оси (attitude/boredom/stress) + жёсткие границы.
- [ ] **P1.** «Психологическое программирование» интимности/доверия (Cappie,
      частично Kind) заменить на 10–15 строк принципов — то, что модель реально
      может исполнять («близость — только после многократного последовательного
      тепла; лав-бомбинг распознаёшь и охлаждаешь»).
- [ ] **P0 (дешёво).** Удалить дословный дубль модуля «Internal Processing» в
      `Kind/Default/Main/main.txt` и дубль Attitude Tiers в его VariablesEffects.
- [ ] **P1.** CoreIntegrityLock (идея Kind — неизменные границы независимо от
      attitude) — хорошая, но ужать до ~5 строк и сделать общим паттерном.
- [ ] **P2.** Довести Creepy/Sleepy до того же скелета — добавить биографию,
      события, вариативность.
- [ ] **P1.** Линтер промптов (в рамках BetterContext уже задуман):
      - лимит токенов на файл,
      - детект дословных дублей блоков,
      - детект упоминаний legacy-тегов и несуществующих команд/ID (см. 01),
      - детект старого синтаксиса перемещения (`walkto, PositionMita ...`).
- [ ] **P2.** Вычистить legacy-механики из шаблонов поставки: `*RP actions*`,
      старый синтаксис `commands: ["walkto, ..."]`, ссылки на форматы, которых
      уже нет.

Комментарий Человека
Можно не удалять все подряд до скелета, но переписывать используя DSL, адаляя псевдологику которая там зашита на реальную.
Кароче, если там есть что-то реально важное для персонажа, думать как это красиво оптивизировать. 


## Затрагиваемые файлы

- `extra/Prompts/Cappie/Default/Main/main.txt` (~33k, худший случай)
- `extra/Prompts/Kind/Default/Main/main.txt` (дубли)
- `extra/Prompts/Kind/Default/Structural/VariablesEffects.txt` (дубль)
- `extra/Prompts/Creepy/Default/Main/main.txt`, `extra/Prompts/Sleepy/Default/Main/main.txt`
- Все `<Char>/Default/Main/` для унификации скелета

## Заметки

- Начинать нормализацию логично с Cappie (худший случай) или с бесплатного
  дедупа Kind. Скелет стоит сначала описать эталоном, затем прогонять по нему
  остальных.
