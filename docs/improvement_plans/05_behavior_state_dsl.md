# 05. Поведенческое состояние через DSL

## Проблема

Сейчас числа и их интерпретация разнесены и дублируются:
- `[Behavior State]` в конце контекста даёт голые числа `Attitude: 60.0, Boredom:
  10.0, Stress: 5.0`.
- Полная статическая таблица **всех диапазонов всех переменных** висит в начале
  промпта (`VariablesEffects.txt`, у Kind ~5k токенов, причём Attitude Tiers там
  задвоена).
- Модель каждый ход должна: найти число в конце → мысленно вернуться в начало →
  выбрать диапазон → не ошибиться. Слабые модели на этом ошибаются.

Идея пользователя: дать DSL возможность выводить **вычисленную линию поведения** в
активный (volatile) контекст, а не держать статтаблицу + дублировать числа.

## Что уже есть в коде

- В `prompt_controller.py` блоки шаблона, начинающиеся с `current context:`, уже
  уходят в volatile-зону (после истории, рядом с памятью и Behavior State) —
  `_VOLATILE_SYSTEM_BLOCK_PREFIXES`. То есть DSL уже *может* класть в активный
  контекст, но только через магический префикс строки.
- `ADD_SYSTEM_INFO` кладёт всегда в статику. Явной команды «в активный контекст» нет.
- `_build_behavior_state_message` формирует `[Behavior State]` автоматически.

## Предложения

- [ ] **P1.** Явная DSL-директива вместо префикса-хака: `ADD_CONTEXT_INFO
      <expr|LOAD ...>` (или `ADD_SYSTEM_INFO ... PLACEMENT context`). Интерпретатор
      собирает третий канал, `_build_system_messages` возвращает его в volatile.
      Префикс `current context:` оставить как deprecated-совместимость.
- [ ] **P1.** `VariablesEffects` разрезать по ролям:
      - *Статика (маленькая, кэшируемая)*: правила **изменения** переменных
        (когда повышать/понижать) — нужны каждый ход, от значения не зависят.
      - *Вычисляемое (volatile)*: только текущая полоса — обращение, тон, 1–2
        реплики-эталона. Одним блоком с числом:
        `Attitude: 62/100 — Warmth: обращение «душка», тон тёплый…`.
        Число оставить обязательно — якорь для выбора величины `*_change`.
- [ ] **P1.** Гистерезис: хранить `attitude_band` (и т.п.) в персистентной
      DSL-переменной, переключать полосу только при выходе за границу с запасом
      (±3), чтобы не мерцать на пороге (59.8 ↔ 60.1). Бонус: смена тона становится
      событием, а не дрожанием.
- [ ] **P2.** Тем же механизмом — гейтинг эмоций у Crazy («smile только при 50+»):
      DSL выводит доступный сейчас поднабор эмоций вместо статических условий.
- [ ] **P2.** Fair Warning Protocol (Kind) как состояние: DSL считает
      предупреждения в переменной и выводит «ты уже дважды предупредила, следующий
      шаг — жёсткая реакция», вместо того чтобы модель выуживала счёт из истории.
- [ ] **P1.** Prompt-feature для подавления дефолтного `[Behavior State]`, если
      персонаж рисует свой блок (по образцу `support_intents=True`), напр.
      `behavior_state=custom`. Нет фичи — старое поведение (обратная совместимость).
- [ ] **P2.** Соглашение для промптеров: все полосы держать в одном `.script`
      рядом (по сути та же таблица, только исполняемая) — чтобы не терялась
      читаемость «а что она делает при attitude 30».

## Затрагиваемые файлы

- `src/DSL/dsl_engine.py` (новая директива)

## Заметки

- Это тот же архитектурный ход, что и в 01: «статичный список-на-все-случаи» →
  «вычисленный срез текущего состояния рядом с запросом».
- Минус, который держать в голове: логика уезжает из читаемого текста в DSL —
  промптерам чуть сложнее видеть картину целиком. Лечится соглашением (последний
  пункт).
