# Агентная отладка промптов через живые API-запросы

**P1** — методология. Не правка контента, а способ вести все остальные правки
из этого плана быстро и с обратной связью.

## Идея

Промптер настраивает провайдера (ключ, модель, пресет) и разрешает агенту
делать через него реальные генерации. Дальше агент крутит цикл «правка промпта →
живой запрос → чтение собранного контекста и ответа → вывод» сам, без GUI и без
ручного прогона игры. Отлаживается три вещи разом:

- **формат** — соблюдение JSON-схемы structured-ответа (`segments`, `*_change`,
  `memory_*`, `commands`);
- **контекст** — что реально склеилось в system/историю/RAG перед запросом;
- **отыгрыш** — тон, характер, реакции на события, работа памяти на дистанции.

## Инструмент

Готовая инфраструктура: `src/utils/Testing/generation_tester/`. Гоняет
**настоящий** пайплайн `Events.Model.GENERATE_RESPONSE` (пресет → сборка промпта →
история → RAG → реальный вызов провайдера → usage/cache/стоимость), без UI.
Механика команд и флагов — в `generation_tester/AGENT_GUIDE.md`. Здесь — как этим
пользоваться для отладки.

Ключевое из механики, что определяет методику:

- по умолчанию **песочница**: `Settings/` и `Histories/` копируются в изолированный
  каталог, боевые данные не портятся. `--live` мутирует историю/память — только осознанно;
- каждый прогон пишет артефакты (`summary.json`, `turn_00N.json`) с ответом,
  токенами, кэшем, стоимостью и полным `last_request_context.json`;
- `--prompts-dir` подсовывает отдельную копию промптов — можно тестировать правку,
  не трогая рабочие `Prompts/`;
- запускать тем же Python, что и приложение (для полного RAG — Venv-python,
  см. каветы ниже).

## Рабочий цикл агента

1. **Правка** промпта в `extra/Prompts/<Char>/...` (или в sandbox-копии `Prompts/`
   под `--prompts-dir`). Править `extra/`, не рабочий `Prompts/` — правило проекта.
2. **Прогон**: `chat` для одиночного хода, `scenario` для многоходового кейса.
3. **Чтение артефактов**:
   - `last_request_context.json` — **что именно ушло в провайдер**: порядок блоков,
     статика vs volatile-зона, что попало из RAG/памяти, дубли, mojibake;
   - ответ Миты — соблюдение JSON-схемы, тон, сегменты, теги действий;
   - токены/кэш — цена правки, регрессия по объёму контекста.
4. **Вывод и следующая правка**. `--repeat N` на одном входе — проверка
   стабильности (формат/тон не «плавают» от прогона к прогону).
5. **Регресс на дистанции**: `scenario` с фиксированным набором ходов гоняется до и
   после правки — сравнить, не сломался ли отыгрыш/память дальше по диалогу.

## Что смотреть под конкретную тему плана

| Тема | На что смотреть в артефактах |
|------|------------------------------|
| Каналы действий (01) | какие `commands`/теги реально выданы, есть ли рассинхрон со списком в контексте |
| Промпты персонажей (02) | объём system-блока в токенах, дубли, псевдокод-модули в собранном контексте |
| Ориентация в мире (03) | mojibake и числа в контексте, попала ли карта дома в запрос |
| Примеры диалогов (04) | соответствуют ли ответы формату примеров |
| DSL поведения (05) | вычисленная линия поведения в volatile-зоне vs статтаблица |
| Безопасность (06) | не протекает ли пароль/DevMode, нейтрализация тегов в ответе |
| Память (08, 09) | что RAG подтянул в контекст, работают ли `memory_*` в ответе |

## Оценка отыгрыша

Сейчас «хорошо/плохо» оценивает агент глазами по артефактам. Для серийных прогонов
имеет смысл добавить **LLM-judge** с чек-листом на персонажа (тон, запретные
паттерны, валидность JSON-схемы) — тогда пачка сценариев даёт сводку регрессий
вместо ручного просмотра. Пока не реализовано — кандидат в отдельный пункт.

## Каветы

- **Живой ключ = деньги/квота.** Каждый прогон реально бьёт в провайдера. Перед
  серией прогонов согласовать бюджет: сколько запросов за итерацию агент делает без
  переспроса. `--repeat` и длинные `scenario` умножают стоимость.
- **RAG в headless.** На игровом `libs/python` RAG работает только в FTS/keyword
  (нет torch/transformers). Для соответствия боевому embedding-поиску запускать
  через `C:\Games\NeuroMita\Venv\Scripts\python.exe`.
- **`--live` мутирует** историю/память/напоминания — для отладки использовать
  песочницу, `--live` только когда осознанно нужен боевой стейт.
- **Диф контекста** между прогонами (что изменилось в собранном промпте после
  правки) делается обычным `diff` по `last_request_context.json` двух прогонов —
  быстрый способ увидеть эффект правки на подачу.

## Что можно доработать (кандидаты в задачи)

- LLM-judge с пер-персонажным чек-листом → сводка регрессий по сценариям.
- Набор эталонных сценариев на каждого персонажа (regression suite промптов).
- Автоматический диф `last_request_context.json` между «до/после» в артефактах прогона.
