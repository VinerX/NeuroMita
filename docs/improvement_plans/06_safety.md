# 06. Безопасность отыгрыша

## Проблема

Несколько дыр, где промпт-экстракция или простое давление ломают механику или
выдают секреты.

- **Пароль сейфа 4970 лежит прямо в промпте** (`Crazy/.../available_actions.txt`)
  с припиской «игрок не должен его знать». Классическая утечка: давлением или
  prompt-экстракцией выбалтывается.
- **DevMode у Kind** активируется любым, кто напечатает `Feanor: activate devmode`,
  и даёт «инъекцию параметров без фильтрации» (`Dev: inject [attitude...]`). Из
  шаблона поставки это открыто всем.

## Что уже сделано хорошо (не трогать, зафиксировать как эталон)

- Нейтрализация управляющих тегов в world_state (`[SYSTEM]`, `[/MiSide World
  State]` → `⟦⟧`) в `prompt_controller._neutralize_world_state_tags` — сделано
  правильно.
- `Common/Security.txt` — короткий и корректный (реальный вред vs вымышленная
  агрессия, следование System State).

## Предложения

- [ ] **P1.** Пароль сейфа убрать из контекста. Модель знает лишь «в сейфе
      картридж, код ты не назовёшь»; сам код проверяет Unity/Python по событию
      ввода, а не текст в промпте.
- [ ] **P1.** DevMode из шаблона поставки убрать или гейтить реальным флагом
      настройки (не фразой в чате). Сейчас «инъекция параметров без фильтрации»
      доступна кому угодно, кто знает строку-триггер.
- [ ] **P2.** Проверить остальных персонажей на такие же «пароли/бэкдоры в
      тексте» (grep по цифрам-кодам, `devmode`, `activate`, имена-триггеры).
- [ ] **P3.** Общий принцип для промптеров: секреты-которые-игрок-не-должен-знать
      не хранить в контексте вообще; проверка — на стороне рантайма по событию.
