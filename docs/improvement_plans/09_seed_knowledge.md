# 09. Нулевые воспоминания / стартовая база знаний

## Главная находка

Система «врождённых знаний» спроектирована правильно, но **по факту почти не
работает — контент оказался сиротой.**

- **`Common/InitialMemories/` никто не подключает.** Ни один файл в `extra/Prompts`
  не ссылается на `game_reality_knowledge_v0.03.script` (37 фактов об устройстве
  мира), `mitas_knowledge.script`, `rooms_knowledge.script`, `start_links.script`.
  В `src` ссылок тоже нет.
- Реально исполняется только `world_knowledge.script` (через `RUN` из init.script):
  ~6 нейтральных фактов + кредиты + канон-блок за флагом `CANONICAL_MISIDE_STORY`
  (по умолчанию выключен). Итого рантайм-база ≈ 6 фактов. Остальное — мёртвый код.

## Что в механике хорошо (сохранить)

- Трёхуровневость: `SEED_MEMORY` (активная память) / `SEED_RAG_MEMORY` (только
  ретрив) / `LINK_ENTITIES` (граф, protected-сущности).
- `SEED_RAG_MEMORY` — элегантно: хранится `is_forgotten=1`, RAG находит, активный
  блок не засоряется. «Фоновая эрудиция» за 0 токенов.
- Языковой гибрид в v0.03 (английский текст + русские ключевые слова в скобках) —
  осознанно хорош для FTS/keyword без torch. Закрепить как стандарт написания сидов.
- Жёсткий канон за явным флагом (`CANONICAL_MISIDE_STORY`) — правильно.

## Проблемы и предложения

### Подключить контент (самое дешёвое)
- [ ] **P1.** Подключить и провести ревизию `Common/InitialMemories/*` — контент
      уже написан, нужно лишь включить в цепочку загрузки (через init.script / RUN).

### Развести по назначению
- [ ] **P1.** Онтология «всегда нужна» (комнаты, кто я, кто рядом) → статика
      промпта / `[House Map]` из 03, **не** в активную память.
- [ ] **P1.** Лор «по запросу» (ядро, картриджи, глюки, 2D-мир, перезагрузки) →
      `SEED_RAG_MEMORY`, а не `SEED_MEMORY`.
- [ ] **P1.** Стартовое отношение → pre-seeded острова:
      `island:relationship = «Ты только познакомилась с игроком, настороженно-
      любопытна»`. Персонаж стартует с внятной позиции, которую сам дальше обновляет.

### `SEED_MEMORY` ест слоты живой памяти
Активные сиды идут в общий пул `MEMORY_CAPACITY=50` с priority High → при
вытеснении переживают Normal-воспоминания о реальных событиях. «В доме есть кухня»
вытесняет «игрок вчера извинился».
- [ ] **P1.** Статичные всегда-истинные факты не должны конкурировать с прожитым
      опытом: перенести в статику промпта или RAG-only (см. выше).

### Provenance и версионирование
Дедуп — по точному тексту. Правка формулировки сида → новая память, старая живёт
рядом и противоречит. Суффиксы `_v0.02`/`_v0.03` в именах — ручной и (без
подключения) неработающий механизм. Сиды в базе неотличимы от органических
(`type="fact"`) — не почистить, не мигрировать.
- [ ] **P1.** Seed-манифест с reconciliation: колонка `seed_key` (+ версия/источник)
      в `memories`; при старте сессии — upsert по ключу изменённых и деактивация
      исчезнувших из промпт-сета. Одна миграция схемы закрывает и «бессмертие», и
      версионирование (хочешь бессмертный сид — флаг в манифесте).

### Сиды бессмертны против воли
init.script исполняется при каждой сборке → удалённый через `memory_delete` сид
возвращается.
- [ ] **P2.** Сделать это осознанным (флаг в манифесте), а не побочкой
      `skip_if_exists` + переисполнения.

### Знания общие, а Миты разные
У Милы (1.0F) и Crazy картины мира противоположны; Creepy предана Crazy, Kind её
ненавидит. `mitas_knowledge.script` для этого и задуман — но не подключён и без
пер-персонажной фильтрации.
- [ ] **P1.** Пер-персонажные наборы: `Common/InitialMemories/` как база +
      `<Char>/InitialMemories/` как надстройка/переопределение, с флагами (в духе
      `CANONICAL_MISIDE_STORY`) на персонажа.

### «Неизвестные неизвестные» / инициатива
Retrieval-only знания всплывают, только когда игрок сам задел тему. Мита не
предложит пойти на кухню / не пошутит про манекены сама, если знание живёт лишь в
RAG-пуле.
- [ ] **P2.** «Оглавление знаний» в статике: одна строка «ты знаешь об устройстве
      мира: ядро, картриджи, манекены, 2D-мир, перезагрузки…» — модель понимает,
      *о чём* спросить свою же память, RAG дальше достаёт детали. Не раздувает статику.
