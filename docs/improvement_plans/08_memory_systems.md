# 08. Системы памяти (саммари / RAG / острова / забывание)

## Вердикт

Костяк рассчитан на долгое общение лучше, чем в большинстве похожих проектов:
layered summary без «испорченного телефона», защищённые острова, двухуровневая
память (активная + забытый пул, находимый RAG'ом), видимая `[RISK]`-зона. С
сильной моделью и включёнными эмбеддингами держит недели связного общения.
Реальные точки отказа — не в архитектуре, а в двух допущениях: «модель сама ведёт
свою память аккуратно» и «ретрив найдёт по одной реплике».

## Что уже сделано хорошо (не ломать)

- **Слоистое сжатие (layered, дефолт)**: каждый кусок суммируется отдельным слоем
  без подмешивания прошлой сводки; редкий роллап старых слоёв пачкой; single-flight,
  cooldown провайдера, отдельный пресет, локальный fallback без LLM.
- **Забывание с прозрачностью**: Low→Normal→High по возрасту, Critical
  неприкосновенен, хвост под `[RISK]`, статистика `N/cap`; забытое уходит в
  forgotten pool и находится RAG'ом (можно реанимировать по `N:id`).
- **Острова**: защищены от забывания, upsert вместо дублей, реактивация забытых,
  4 валидируемых типа.
- **Гибридный RAG**: вектор + keyword + FTS + linear rerank + опц. cross-encoder,
  graceful degradation без эмбеддингов.

## Проблемы и предложения

### Куратор памяти (иначе оперативка замусорится)
Вся гигиена (dedup, update-vs-add, приоритеты, обновление островов, merge) — на
дисциплине модели в каждом ответе. На слабых моделях за пару вечеров: дубли,
«игрок поздоровался» с priority high, острова не обновлялись. Вытеснение ранжирует
только по priority+возрасту, не по полезности → выталкивает ценное.

- [ ] **P1.** Фоновый maintenance-проход в пуле `BACKGROUND_LLM` (раз в N
      сообщений / на idle): dedup+merge, переприоритизация, обновление островов.
- [ ] **P1.** Dedup на вставке `memory_add`: сравнивать similarity с
      существующими (эмбеддинги памятей уже есть) → авто-merge или отклонение с
      логом. Один запрос к своей же базе, без LLM.
- [ ] **P2.** Учитывать «полезность» при забывании: вести `last_retrieved` /
      `retrieval_count` (RAG знает, что всплывало) и подмешивать в ранг вытеснения.

### RAG слеп к контексту диалога
`process_rag` эмбеддит только текущую реплику. Короткие фразы («а помнишь?», «про
это самое») → шум или ничего не проходит порог 0.4. Анафора не резолвится.

- [ ] **P1.** Конкатенировать в запрос последние 1–2 обмена (даёт больше всего
      прироста дёшево).
- [ ] **P2.** Опц. фоновая переформулировка запроса маленькой моделью для коротких
      реплик; либо сжатие заодно возвращает «текущие темы» и подмешивает в RAG-запрос.

### Русская морфология в FTS-режиме
В боевом `libs/python` нет torch → RAG падает в FTS/keyword-only. SQLite FTS5 с
дефолтным токенизатором не стеммит русский: «играли» не найдёт «играть». У основной
массы игроков recall архива тихо ниже задуманного.

- [ ] **P1.** Лёгкий snowball-стеммер (ru) при индексации и в запросе для
      FTS/keyword-путей — чистый Python, без ML-зависимостей.
- [ ] **P2.** Замерить это в rag_tester именно в keyword-режиме (не только с
      эмбеддингами).

### Саммари и долгая память не связаны
Событие: окно → слой сводки → роллап в «вы общались». Если модель не положила его
в память сама — деградирует до каши безвозвратно.

- [ ] **P1.** При каждом сжатии куска просить LLM тем же запросом выдать 0–3
      кандидата в долгую память (structured), прогонять через тот же dedup/upsert.
      Сжатие становится страховочным вторым путём в память.

### Мелочи
- [ ] **P2.** Сводка пишется по-английски (`compression_prompt.txt`: «in english»)
      при русском диалоге — теряются клички/интонации/формулировки, провоцирует
      языковой дрейф. Суммировать на языке диалога.
- [ ] **P2.** `previous_summary` молча режется по 6000 символов
      (`_truncate_text_for_prompt`) — тихая потеря старейшего контекста (не-layered).
- [ ] **P2.** Рендер слоёв в `[HISTORY SUMMARY]` без токен-бюджета — capнуть
      суммарный размер, форсировать роллап по символам, а не только по числу слоёв.
- [ ] **P2.** Инструкции по памяти размазаны по трём местам (response_format_json,
      main персонажей, wrapper-подсказки в `get_memories_formatted`) — свести к
      одному источнику (та же болезнь, что в 01/05).
- [ ] **P2.** «Прошло время» модель не чувствует: даты в памяти есть, но нет строки
      `Last conversation: 3 days ago` в `[Current State]` (пересекается с 07).
- [ ] **P3.** Граф: мусорные сущности от слабых моделей никто не чистит; тот же
      maintenance-проход мог бы схлопывать синонимы («Игрок»/«игрок»/«Player»).

## Затрагиваемые файлы

## Порядок

Начинать с: (1) фоновый куратор + dedup на вставке, (2) контекстный RAG-запрос,
(3) русский стеммер для FTS. Это три реальные точки отказа на длинной дистанции.
